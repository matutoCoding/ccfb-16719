# 文物碎片三维拼对系统

浏览器端的陶瓷碎片三维拼对工作台：TypeScript + Three.js + Web Worker + IndexedDB。无需后端，几何文件和档案数据均保存在本机浏览器。

## 安装与启动

```bash
pnpm install
pnpm dev
```

构建与类型检查：

```bash
pnpm build
pnpm preview
```

核心算法验收脚本（Node 24 可直接执行 TypeScript）：

```bash
pnpm benchmark
```

> 按你的本机偏好，依赖没有被自动安装；首次运行前需要手动执行一次 `pnpm install`。

## 页面

- `#/artifacts` 器物档案：出土单位、器型、材质、年代、描述，一件器物挂全部碎片和步骤。
- `#/fragments` 碎片管理：多文件导入 PLY/OBJ，自动区分器表、内壁、原始口沿/底和粗糙断面；支持点选三角面手动修正，按大小和纹饰分组。
- `#/match` 自动拼对：Worker 计算断面轮廓、曲率、器表法向、纹饰连续性和断面墙支撑，候选对按得分排序；每一步保留分数、依据和前后矩阵，可撤销/重做。
- `#/manual` 手动调整：TransformControls 平移/旋转，松手保存并锁定；可按候选关系吸附到最近匹配位姿，锁定片不会被自动结果覆盖。
- `#/restore` 复原预览：显示整器和按旋转对称轴生成的蓝色半透明补全胎体；导出合并 OBJ、每片列主序 `mat4` JSON、拼接顺序 SVG。
- `#/settings` 设置验收：权重、阈值、吸附半径、轴归一化开关，可重建测试数据、清空 IndexedDB、运行浏览器 Worker 验收。

## 测试数据

`src/core/generate.ts` 程序化生成两套毫米单位模型：

- 罐：4 × 6 = 24 个分区，丢弃 3 片，保留 21 片；高 260 mm，最大半径 152 mm。
- 碗：3 × 9 = 27 个分区，丢弃 4 片，保留 23 片；高 96 mm，半径 164 mm。

碎片包含外表面、内表面、断面墙和原始口沿/底面；断面墙加入相干三维噪声。罐带弦纹/卷草，碗带弦纹/莲瓣，顶点色用于纹饰连续性评分。

## 核心流程

1. `classify.ts`：邻接法向、局部粗糙度和连通域识别器表/断面；导入模型会自动执行。
2. `contours.ts`：提取器表与断面的交界轮廓，弧长重采样并生成滑动窗口描述。
3. `kabsch.ts`：无依赖 3×3 Jacobi 特征分解和 Kabsch 刚体对齐。
4. `matcher.ts`：枚举轮廓窗口和正反方向，做弧长偏移搜索、平移 ICP、曲率/法向/颜色评分、断面点云支撑验证。
5. `assemble.ts`：Kruskal 最大置信生成树、位姿反推、吸附位计算和真值误差评估。
6. `lathe.ts`：旋转器型全局约束。外表面点满足 `radius = profile(y)`，通过线性圆/轴位拟合加 Gauss-Newton 精修，把每片校正到整器坐标系。
7. `matcher.worker.ts`：全部匹配计算放在 Web Worker，主线程只负责 Three.js 渲染和交互。
8. `db.ts`：IndexedDB 保存档案、碎片网格、步骤和设置。

## 验收口径

`pnpm benchmark` 会生成罐/碗、执行完整候选匹配和旋转器型校正，并用程序生成时保存的 `truthMatrix` 比较：

- 最大质心位置误差 `< 1 mm`
- 最大角度误差 `< 1°`
- 21 片罐的完整计算通常约 15–25 秒（Node 基准；浏览器 Worker 会受设备性能影响）

旋转器型约束是题目明确要求的约束之一；它与断面匹配、器表曲率和纹饰连续性共同参与，而不是只依赖单一断面分数。

## 导出矩阵约定

JSON 中每个 `matrix` 是与 `THREE.Matrix4.fromArray()` 兼容的 16 元素列主序数组，把以碎片质心为原点的局部坐标变换到整器坐标。合并 OBJ 已应用这些矩阵，可直接在 Blender、MeshLab 或 Three.js 中打开。
